# Video Prompt Director 전문 모듈 연결

## 현재 적용 범위

기존 에이전트 지침을 보존하면서 공통 지침과 선택한 화풍의 전문 지침을 합성하는 실행 기반입니다. 기존 에이전트는 기본적으로 비활성화 상태를 유지합니다. 공통·2D·3D·실사 지침 본문은 아직 제공되지 않았으므로 기본 레지스트리도 모두 비활성화되어 있습니다. 현재 실행에서는 기존 지침을 사용합니다.

이 단계에는 관리자 편집 UI, AI 기반 화풍 분류, 전문 지침 본문, 실제 공급자 호출 검증은 포함하지 않습니다. 입력의 화풍을 추측하지 않고 명시적인 값만 사용합니다.

## 에이전트 설정 계약

에이전트 정의의 선택적 `video_prompt_modules` 필드로 구성합니다. 별도 DB 마이그레이션 없이 기존 JSON 정의와 실행 계약에 저장합니다.

```json
{
  "video_prompt_modules": {
    "enabled": true,
    "mode": "auto",
    "profile_id": null,
    "user_style_field": "requested_style",
    "confirmed_style_field": "confirmed_style",
    "reference_style_field": "reference_style",
    "metadata_style_field": "media_metadata"
  }
}
```

`*_field`는 실행 입력에서 조회할 최상위 필드 이름입니다. 값은 `animation_2d`, `animation_3d`, `live_action` 중 하나이거나, 해당 값을 `media_type`에 담은 객체여야 합니다. 자유 서술문이나 이미지에서 자동 추론하지 않습니다. 수동 선택은 `mode: "manual"`과 `profile_id`로 지정합니다.

선택 우선순위는 수동 지정 → 사용자 입력 → 확정된 스타일 → 참고 스타일 → 메타데이터입니다. 서로 다른 유효 값이 있으면 우선순위대로 선택하고 충돌 정보를 기록합니다. 수동 모드에 프로필이 없으면 다른 입력으로 임의 선택하지 않습니다. 알 수 없는 값은 전문 모듈을 선택하지 않습니다.

## 지침 본문 제공 후 활성화

1. 제공받은 본문을 `services/backend/src/asa/prompt_modules/` 아래 신뢰된 Markdown 파일로 추가합니다.
2. `video_prompt_modules.py`의 레지스트리에 파일명과 명시적인 버전을 등록합니다. 기본 파일명은 `director.md`, `animation-2d.md`, `animation-3d.md`, `live-action.md`입니다.
3. 공통 모듈과 사용할 전문 모듈의 `enabled`를 활성화합니다. 공통 모듈이 없거나 읽을 수 없으면 전문 모듈만 단독 적용하지 않습니다.
4. 대상 에이전트 설정에서 연결을 활성화하고 입력 필드 매핑을 지정합니다.
5. 새 요청으로 합성 결과와 선택 기록을 확인합니다. 이미 접수한 요청은 이전 스냅샷을 유지합니다.

파일 경로는 레지스트리에서만 지정하며 모듈 디렉터리 밖의 경로나 Markdown 이외의 파일은 읽지 않습니다. 비활성·누락·빈 파일 등은 경고로 기록하고 사용 가능한 공통 모듈 또는 기존 지침으로 실행합니다. 레지스트리의 `compatible_modes`, `selection_priority`는 확장용 메타데이터이며 현재 실행 제한이나 선택 순위에 사용하지 않습니다.

## 실행과 추적

개별 요청은 접수 시 `video_prompt_bundle`에 합성 지침을 고정합니다. 자동화는 접수 시 신뢰된 모듈 본문을 `video_prompt_catalog`로 고정하고, 해당 단계 입력이 정해진 뒤 모듈을 선택하여 단계 실행 기록에 번들을 저장합니다. 이후 파일 변경이 이미 접수한 실행에 섞이지 않습니다. 이전 계약에 번들이 없으면 기존 지침으로 실행합니다.

번들에는 선택 방식·출처·화풍, 적용 모듈 ID와 버전·SHA-256, 충돌·경고, 대체 실행 여부, 최종 지침과 `prompt_bundle_version`이 포함됩니다. 이는 실행 계약과 자동화 단계 기록이며 별도 조회 UI는 아직 없습니다.

합성 순서는 공통 지침 → 선택한 전문 지침 → 기존 에이전트 지침입니다. 사용자 실행 입력은 기존 입력 경로로 전달하며 모듈 본문으로 취급하지 않습니다. 이 계층은 대본·장면·이미지·캐릭터 연결 및 모델 제한을 변환하지 않습니다. 기존 실행 경로의 입력과 모델 설정을 유지합니다.

## 검증 기록

2026-11-06 구조 재검토:
- 문자열·배열 입력에서도 필드 매핑 조회가 예외 없이 기존 지침으로 대체되도록 보완했습니다. 원래 사용자 입력은 변경하지 않습니다. 두 회귀 사례의 수정 전 실패와 수정 후 통과를 확인했습니다.
- 모의 모델 호출로 활성 모듈의 고정된 번들이 실제 system 메시지에 전달되며 이후 본문 파일 변경의 영향을 받지 않는 것을 확인했습니다. 모듈 테스트 25건 통과.
- 개별 접수 번들 및 순차·그래프 자동화의 카탈로그 고정/단계 번들 저장 연결을 코드로 검토했습니다. 활성 모듈을 사용한 DB 큐·그래프 통합 실행은 미검증입니다.
- 현재 레지스트리의 네 모듈은 비활성이며 전문 지침 본문이 없습니다. 구조 연결은 구현됐지만 실제 전문 프롬프트 활성화·생성 품질 검증은 완료되지 않았습니다.

이전 구현 시점 검증:

- 신규 모듈 테스트 22건을 포함한 전체 backend pytest 357건 통과.
- backend mypy 63개 소스 통과, 변경한 backend 파일의 ruff 통과.
- frontend typecheck 및 production build 통과.
- 전체 ruff는 기존 작업 기록과 같은 97건 오류가 남아 있습니다.
- Windows 기본 임시 테스트 경로 권한 오류는 프로젝트 내부 `--basetemp=.test-tmp/modules-full-final`로 재실행하여 해소했습니다. 전체 테스트 종료 뒤 DB 풀 연결 시간 초과 경고 1줄이 출력되었으며 테스트 실패는 없었습니다.
- UI 변경 및 유료 AI 호출은 수행하지 않았습니다. 전문 지침 활성화와 실제 생성 품질은 본문 제공 후 검증해야 합니다.
