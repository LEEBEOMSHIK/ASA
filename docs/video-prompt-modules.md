# Video Prompt Director 전문 모듈 연결

## 현재 적용 범위

기존 에이전트 지침을 공통으로 사용하고 실행 시 사용자가 선택한 영상 스타일의 추가 지침을 합성합니다. 영상 프롬프트 설정의 기본 동작이며 사용 체크박스나 고정 스타일 모드는 없습니다. 기존 영상 모델 입력 계약(`x-video-model`) 또는 화면 관리 지침을 가진 에이전트는 편집/저장 시 표준 영상 스타일 필수 입력을 갖습니다. 기존 DB 설정과 원문을 임의 저장하지 않으며 최초 편집 시 저장 필요를 표시합니다. 기존에 접수된 작업은 원래 snapshot을 유지합니다.

## 화면에서 사용하기

1. 에이전트 → 대상 에이전트 설정 편집 → **에이전트 기본 설정**에서 기존 **에이전트 지침**을 공통 본문으로 사용합니다. 바로 아래에 스타일별 추가 지침이 항상 표시되며 체크박스가 없습니다.
2. 관리자(owner/admin)는 기존 **에이전트 지침 · 공통**을 편집합니다. 동적 지침을 관리하는 에이전트에서는 일반 사용자에게 공통 입력란을 숨기고 서버도 원문 변경·삭제와 관리 설정 제거를 거절합니다. 별도 공통 지침 입력란을 중복 제공하지 않습니다.
3. **편집할 영상 스타일**에서 2D 애니메이션/3D 애니메이션/실사를 선택하고 추가 지침을 작성합니다. 편집 대상을 전환해도 미저장 내용은 유지됩니다. 크게 편집도 지원합니다.
4. 에이전트 하단 **저장**을 누릅니다. 일부 스타일이 미작성이어도 나머지 설정과 본문을 저장할 수 있습니다. 미작성 스타일은 안내를 표시하고 그 스타일로 실행하는 요청은 서버에서 거절합니다.
5. 실행 화면에서 필수 **영상 스타일**(2D 애니메이션/3D 애니메이션/실사)을 선택합니다. 선택한 스타일 본문만 공통 지침 뒤에 추가됩니다. 선택이 없거나 유효하지 않으면 실행하지 않습니다. 설정의 편집 대상 선택은 실행 스타일을 고정하지 않습니다.

공통 본문은 기존 `instructions`, 스타일별 본문은 `video_prompt_modules.style_instructions`에 저장됩니다. `editor_managed`는 화면 관리 방식 표시입니다. 이전 구현의 `common_instructions`는 호환용으로 보존하지만 새 실행에는 중복 합성하지 않습니다. 작업 공간별 에이전트 버전/충돌 검사를 재사용하며 별도 브라우저 저장을 사용하지 않습니다. 각 본문은 65,536자 이하, 에이전트 저장 요청은 JSON 이스케이프 여유를 포함해 4MiB 이하입니다. 일반 사용자의 수정은 서버가 잠근 이전 에이전트 설정과 비교하여 공통 본문을 보호합니다.

실제 공급자 호출 품질 검증은 포함하지 않습니다. 입력의 화풍을 추측하지 않고 명시적인 값만 사용합니다. 기존 에이전트 지침을 그대로 공통으로 쓰며, 스타일 본문을 임의 작성해 저장하지 않았으므로 사용할 스타일의 지침은 설정에서 작성해야 합니다.

## 에이전트 설정 계약

현재 화면 관리 계약은 `selection_required: true`이며 `enabled: true`, `editor_managed: true`, `mode: auto`, `user_style_field: video_style`로 정규화합니다. 예전 체크박스/수동 모드 값으로 새 동작을 끌 수 없습니다. 입력 스키마에는 세 화풍 enum을 갖는 필수 `video_style`을 추가하고 실행 UI에서 한글 선택지로 표시합니다. 기존 같은 이름의 다른 입력은 덮어쓰지 않고 이름 변경을 안내합니다. 아래 수동 모드/매핑/파일 활성화 설명은 이전 파일 기반 계약의 호환 문서입니다.

에이전트 정의의 선택적 `video_prompt_modules` 필드로 구성합니다. 별도 DB 마이그레이션 없이 기존 JSON 정의와 실행 계약에 저장합니다.

```json
{
  "video_prompt_modules": {
    "enabled": true,
    "mode": "auto",
    "profile_id": null,
    "user_style_field": "requested_style",
    "confirmed_style_field": "confirmed_style",
    "reference_style_field": "reference_style",
    "metadata_style_field": "media_metadata"
  }
}
```

`*_field`는 실행 입력에서 조회할 최상위 필드 이름입니다. 값은 `animation_2d`, `animation_3d`, `live_action` 중 하나이거나, 해당 값을 `media_type`에 담은 객체여야 합니다. 자유 서술문이나 이미지에서 자동 추론하지 않습니다. 수동 선택은 `mode: "manual"`과 `profile_id`로 지정합니다.

선택 우선순위는 수동 지정 → 사용자 입력 → 확정된 스타일 → 참고 스타일 → 메타데이터입니다. 서로 다른 유효 값이 있으면 우선순위대로 선택하고 충돌 정보를 기록합니다. 수동 모드에 프로필이 없으면 다른 입력으로 임의 선택하지 않습니다. 알 수 없는 값은 전문 모듈을 선택하지 않습니다.

## 지침 본문 제공 후 활성화

1. 제공받은 본문을 `services/backend/src/asa/prompt_modules/` 아래 신뢰된 Markdown 파일로 추가합니다.
2. `video_prompt_modules.py`의 레지스트리에 파일명과 명시적인 버전을 등록합니다. 기본 파일명은 `director.md`, `animation-2d.md`, `animation-3d.md`, `live-action.md`입니다.
3. 공통 모듈과 사용할 전문 모듈의 `enabled`를 활성화합니다. 공통 모듈이 없거나 읽을 수 없으면 전문 모듈만 단독 적용하지 않습니다.
4. 대상 에이전트 설정에서 연결을 활성화하고 입력 필드 매핑을 지정합니다.
5. 새 요청으로 합성 결과와 선택 기록을 확인합니다. 이미 접수한 요청은 이전 스냅샷을 유지합니다.

파일 경로는 레지스트리에서만 지정하며 모듈 디렉터리 밖의 경로나 Markdown 이외의 파일은 읽지 않습니다. 비활성·누락·빈 파일 등은 경고로 기록하고 사용 가능한 공통 모듈 또는 기존 지침으로 실행합니다. 레지스트리의 `compatible_modes`, `selection_priority`는 확장용 메타데이터이며 현재 실행 제한이나 선택 순위에 사용하지 않습니다.

## 실행과 추적

개별 요청은 접수 시 `video_prompt_bundle`에 합성 지침을 고정합니다. 자동화는 접수 시 신뢰된 모듈 본문을 `video_prompt_catalog`로 고정하고, 해당 단계 입력이 정해진 뒤 모듈을 선택하여 단계 실행 기록에 번들을 저장합니다. 이후 파일 변경이 이미 접수한 실행에 섞이지 않습니다. 이전 계약에 번들이 없으면 기존 지침으로 실행합니다.

번들에는 선택 방식·출처·화풍, 적용 모듈 ID와 버전·SHA-256, 충돌·경고, 대체 실행 여부, 최종 지침과 `prompt_bundle_version`이 포함됩니다. 이는 실행 계약과 자동화 단계 기록이며 별도 조회 UI는 아직 없습니다.

화면 관리 방식의 합성 순서는 기존 에이전트 지침(공통, 한 번만) → 선택한 스타일의 추가 지침입니다. 새 catalog의 공통 항목에 출처를 기록해 중복 합성을 막습니다. 이미 접수된 이전 catalog/bundle은 원래 합성 순서를 유지합니다. 기존 파일 기반 연결은 호환을 위해 공통 파일 → 전문 파일 → 에이전트 지침 순서를 유지합니다. 사용자 실행 입력은 기존 입력 경로로 전달하며 모듈 본문으로 취급하지 않습니다. 이 계층은 대본·장면·이미지·캐릭터 연결 및 모델 제한을 변환하지 않습니다.

## 검증 기록

2026-11-06 구조 재검토:
- 문자열·배열 입력에서도 필드 매핑 조회가 예외 없이 기존 지침으로 대체되도록 보완했습니다. 원래 사용자 입력은 변경하지 않습니다. 두 회귀 사례의 수정 전 실패와 수정 후 통과를 확인했습니다.
- 모의 모델 호출로 활성 모듈의 고정된 번들이 실제 system 메시지에 전달되며 이후 본문 파일 변경의 영향을 받지 않는 것을 확인했습니다. 모듈 테스트 25건 통과.
- 개별 접수 번들 및 순차·그래프 자동화의 카탈로그 고정/단계 번들 저장 연결을 코드로 검토했습니다. 활성 모듈을 사용한 DB 큐·그래프 통합 실행은 미검증입니다.
- 현재 레지스트리의 네 모듈은 비활성이며 전문 지침 본문이 없습니다. 구조 연결은 구현됐지만 실제 전문 프롬프트 활성화·생성 품질 검증은 완료되지 않았습니다.

이전 구현 시점 검증:

- 신규 모듈 테스트 22건을 포함한 전체 backend pytest 357건 통과.
- backend mypy 63개 소스 통과, 변경한 backend 파일의 ruff 통과.
- frontend typecheck 및 production build 통과.
- 전체 ruff는 기존 작업 기록과 같은 97건 오류가 남아 있습니다.
- Windows 기본 임시 테스트 경로 권한 오류는 프로젝트 내부 `--basetemp=.test-tmp/modules-full-final`로 재실행하여 해소했습니다. 전체 테스트 종료 뒤 DB 풀 연결 시간 초과 경고 1줄이 출력되었으며 테스트 실패는 없었습니다.
- UI 변경 및 유료 AI 호출은 수행하지 않았습니다. 전문 지침 활성화와 실제 생성 품질은 본문 제공 후 검증해야 합니다.

영상 스타일 입력은 고정된 필수 선택으로 표시하며 선택지·입력 방식·기본값 편집을 제공하지 않는다. 기존 선택지가 달라진 초안은 해당 항목만 복구한 뒤 저장한다. 공통 및 스타일 지침과 나머지 설정은 유지한다.

## 스타일별 모델 안내 (2026-11-06)
실행 및 미리보기에서 영상 스타일을 모델보다 먼저 표시하고 선택 스타일을 모델 안내에 전달한다. 현재 활성 모델 Runway Gen-4.5는 공식 소개와 이미지→영상 가이드 기반 안내를 제공한다. 이미지가 화풍·구도의 기준이라는 공식 특성과 스타일별 활용 제안을 구분한다. 모델/스타일 변경은 다른 입력값을 바꾸지 않는다. 자료 없는 모델은 미확인으로 표시한다. 안내 데이터는 apps/web/lib/video-model-guidance.ts에서 관리하며 별도 관리자 안내 편집 UI는 포함하지 않는다.
