# 디자인 시스템 v0.2

제품 원칙: 제작 과정과 다음 행동이 명확한 작업 공간. 정보 밀도보다 검토·수정의 안정성을 우선한다.
정본은 apps/web/app/tokens.css, 공통 컴포넌트는 apps/web/components/ui.tsx다.
새 화면에서 색상·간격·모서리 값을 임의로 복제하지 않는다.

## 토큰

사용자 선택에 따라 밝고 정돈된 작업 도구 스타일을 기본으로 한다.
light: canvas #f7f8fa, surface #ffffff, text #20252e, muted #626b78,
border #dfe3e9, primary #5146d9, on-primary #ffffff.
기본은 밝게이며 화면 모드에서 밝게/어둡게/시스템 설정을 선택한다. 선택은 브라우저에 저장하고
고객·관리자·로그인 화면에 공통 적용한다. 시스템 설정을 선택한 경우에만 OS 테마 변경을 따른다.
dark: canvas #101522, surface #192132, text #eef2fa, muted #b3bfd3,
border #45516a, primary #a8b5ff, on-primary #17204e, accent-soft #2b3150.
첫 렌더링 전에 저장된 테마를 적용하고 네이티브 입력 요소의 color-scheme도 맞춘다.
success/warning/danger는 background + foreground 쌍으로 제공한다.
간격 4/8/12/16/24/32/48px; radius 6/10/16px; 본문 16px, 보조 14px, 제목 24/32px.
글꼴은 시스템 UI + Malgun Gothic. 외부 폰트 다운로드 없이 실행한다.
본문 line-height 1.6, 포커스 3px, 기본 조작 높이 44px, reduced-motion을 존중한다.

## 컴포넌트 계약

최근 작업의 AI 실행 상태와 후속 작업 상태를 분리한다. 후속 작업은 종류명과 항목별 개수로 요약하며,
진행 상태를 색상/점만으로 표현하지 않는다. 제외는 되돌릴 수 있는 선택으로 표시하고 기존 결과를 삭제하지 않는다.
상세의 이어서 작업 버튼과 항목별 확인 링크로 원래 결과 영역에 이동한다.

본문 및 출처 링크에도 밑줄을 사용하지 않는다. 외부 출처는 공통 ExternalLink를 사용하며,
작은 외부 이동 아이콘·텍스트·hover 배경으로 구분한다. 기본/hover/focus 모두 밑줄 없이
키보드 포커스 테두리를 유지한다. 출처 묶음은 12px 간격과 자동 줄바꿈을 사용한다.

공통 탐색은 ui.tsx의 StudioNavigation을 사용한다. 작업 공간 → 자동화 빌더 → 에이전트 →
도구 라이브러리 순서를 모든 화면에서 유지한다. 링크는 밑줄 없는 아이콘+텍스트 행,
44px 이상 높이, hover 배경, aria-current=page와 강조 배경/점으로 현재 위치를 표시한다.
‘새 작업’은 별도 primary 행동 버튼이며 화면 이동 메뉴와 분리한다.
고객 화면의 최근 작업은 탐색 아래에 유지한다. 관리/빌더 화면도 동일한 왼쪽 메뉴를 사용한다.
작은 화면은 고객 dialog 메뉴 및 관리 화면 접이식 메뉴로 모든 경로를 제공한다.
빌더는 탐색과 구별되는 블록 목록·작업 흐름·설정 패널로 나누며 패널 제목은 16px,
페이지 제목은 32px, 간격/색상/모서리는 기존 토큰을 따른다. 넓은 빌더 작업 영역은 1600px까지 허용한다.

현재: Button(primary/secondary), Card, StatusBadge(neutral/success/warning/danger), Field.
Button은 native disabled/type 속성과 키보드 동작을 보존한다.
Field는 label과 control ID를 연결하고 hint/error를 aria-describedby로 연결한다.
오류는 aria-invalid와 문장으로 표현하며 색상만으로 구분하지 않는다.
예정: Dialog(초점 가두기·ESC·복귀), Toast(상태 알림), Tabs(키보드 이동),
Stepper(현재 단계), AssetCard(버전·출처), VideoPreview(키보드 재생·자막).
예정 컴포넌트는 해당 기능 작업 때 접근성 검증과 함께 구현한다.

## 화면과 UX 표준

- 자동화 목록과 편집은 분리한다. 편집의 기본 화면에는 이름/저장 상태/행동과 작업 흐름만 표시한다.
- 단계 추가는 연결선의 ＋에서 선택창을 연다. 전체 도구 목록을 상시 펼치지 않는다.
- 설정은 블록 선택 시, 테스트는 상단 버튼 요청 시에만 표시하며 닫을 수 있다.
- 시작/작업/결과의 형태를 구별하고 내부 ID/자료형은 기본 설명에 노출하지 않는다.
- 작업 선택창은 native dialog로 초점 가두기·Escape 닫기를 제공한다.

- 에이전트 편집은 역할 예시 → 맡길 일 → 받을 정보/만들 결과 → 선택 도구 순서로 안내한다.
- 기술 용어 대신 질문과 구체적인 예를 먼저 제공한다. 필드 키·자료형·모델·한도는 고급 설정으로 접는다.
- 요약 패널은 현재 설정을 설명하며 실제 생성 결과나 성공한 실행을 암시하지 않는다.
- 기본 조작은 초안 저장과 도구 등록. 등록 시 서버 검증하며 작업 공간 내부 등록임을 설명한다.

- 탐색: 프로젝트 → 제작 설정 → 대본 검토 → 소재 검토 → 영상 검토·내보내기.
- 프로젝트 화면: 제목·컨셉·현재 버전·최종 작업 상태·다음 행동을 우선 표시한다.
- 생성 전: 예상 비용·모델·길이·비율·사용할 자료를 확인하고 제출 중 중복 요청을 막는다.
- 승인: 승인 대상 버전을 고정한다. 편집 후 기존 승인 유효 여부를 명확히 표시한다.
- 진행: 단계 이름과 대기 원인을 표시한다. 측정 불가능한 진행률·완료 시간을 만들지 않는다.
- 오류: 무엇이 실패했는지, 결과·과금이 확실한지, 재시도 가능 여부를 표시한다.
- 취소: 요청 중 / 중단 확인 완료를 구분한다. 취소가 이미 발생한 비용의 환불을 뜻하지 않는다.
- 빈 화면: 데이터가 없다는 설명과 가능한 다음 행동. 초기 구성 화면에 가짜 제작 이력을 넣지 않는다.
- 미구현 기능: 버튼을 비활성화하고 이유를 인접 문장으로 설명한다.
- 저장: 변경 내용을 보존하고 저장 성공/실패를 표시한다. 로컬 초안과 서버 저장을 구분한다.
- 반응형: 360px부터 가로 스크롤 없이, 넓은 화면은 최대 1120px 작업 영역.
- 접근성 목표: WCAG 2.2 AA, 본문 대비 4.5:1, 키보드만으로 모든 주요 작업 가능.

## 수용 기준

light/dark, 360/768/1440px, 키보드 Tab/Enter/ESC, loading/empty/error/success/disabled를 점검한다.
스크린리더 label·오류 연결을 확인한다. UI 검증 없이 디자인 시스템 전체 완료를 선언하지 않는다.

## 에이전트·자동화 확장 화면 (구현 예정)

[상세 설계](agent-automation-design.md)의 화면과 상태 계약을 따른다.
- AgentEditor: 역할·모델·입출력·허용 도구·한도·버전. 비밀키 입력/표시는 서버 설정 화면과 분리.
- ToolPicker: ASA 도구/내 에이전트 구분, 버전·사용 가능 여부·이유 표시.
- WorkflowEditor: 블록 목록·연결·설정·검증 오류. 드래그와 동등한 키보드 폼 제공.
- RunTree: root→step→agent→tool 계층, 현재 선택과 상태를 텍스트로 표시.
- ResultInspector: 입력·결과·자산·시간·사용량·오류. 출력은 텍스트/안전한 미리보기로 렌더링.
- ApprovalPanel: 승인 대상 버전·변경점·실행 비용 영향. 오래된 승인 요청이면 갱신 안내.
- BudgetSummary: 추정/예약/확정/미확정 구분. 상위·하위 비용을 중복 합산하지 않음.
실행과 편집 화면을 구분하고 게시된 버전, 현재 초안, 실행에 쓰인 버전을 각각 표시한다.
SSE 연결이 끊겨도 마지막 확인 상태와 재연결 표시를 유지하며 실행 실패로 바꾸지 않는다.
미실행 분기는 skipped, 취소 요청은 cancel_requested, 결과 불명확은 needs_attention으로 구분한다.


### 자동화 바로가기와 실행 화면 (ASA-033)
- 목록 카드는 편집/실행/시간 예약/기록을 독립 버튼으로 표시한다. 중첩 버튼을 만들지 않는다.
- 실행 화면은 요청과 단계별 결과를 분리하고, 좁은 화면에서는 세로로 배치한다.
- 생성 전 결과 예시를 실제 결과처럼 채우지 않는다. 대기/진행/확인/완료를 텍스트로 표시한다.
- 예약 시간은 한국 시간임을 입력 옆에 명시하고 저장된 구성 버전·다음 실행·꺼짐 상태를 표시한다.
- 승인 버튼은 화면에 표시된 단계에만 적용한다. 결과 불확실 상태에는 새 작업 준비와 확인 안내를 제공한다.
- 현재 금액 추정은 미지원이며 가짜 금액을 표시하지 않는다. 실제 API 비용 가능성을 제출 전에 알린다.

### 자유 연결 자동화 빌더 (ASA-035)
- 그래프 편집에서는 연결선의 방향이 실행 순서다. 위치 이동이 연결/실행 순서를 바꾸지 않는다.
- 새 자동화는 시작/결과 블록으로 시작한다. 도구·직접 AI·조건·반복 추가는 별도 선택창으로 제공한다.
- 조건 출력은 ‘예’/‘아니요’, 반복 출력은 ‘각 항목’/‘완료 후’로 이름 붙인다. 색상만으로 구분하지 않는다.
- 캔버스는 내부 이동/확대를 허용하되 모바일 페이지 전체가 가로로 넘치지 않게 한다.
- 마우스 드래그 외에 키보드 위치 조절과 출력별 목적지 선택으로 동일한 구성을 만들 수 있어야 한다.
- 설정은 선택한 블록만 표시하고 연결 설명은 실제 출처 블록 이름/결과 항목으로 표현한다.
- 직접 AI 요청은 지시문, 전달할 내용, 답변 형식(글/목록)을 바로 작성한다. 에이전트 등록을 강제하지 않는다.
- 목록 반복은 ‘현재 항목’, ‘반복 결과 목록’을 구분하고 항목수 제한과 반환 연결을 설명한다.
- 실행 기록에서는 방문한 경로·반복 회차별 결과를 표시하며 선택되지 않은 경로에 가짜 결과를 채우지 않는다.
- 연결 검사는 잘못된 블록/출력 경로를 이름으로 가리킨다. 저장과 실제 실행 가능 여부를 구분한다.

### 연결 상태와 작업 선택 (ASA-036)
- 복잡한 배치는 다른 블록을 피하는 둥근 경로를 사용한다. 겹침으로 안전한 경로가 없으면 점선과 텍스트로 위치 수정을 안내한다. 드래그 중 임시 연결을 표시하고 놓을 때 전체 경로를 정리한다. 선끼리의 교차 제거는 보장하지 않는다.
- 블록의 경로 이름(다음/맞으면/각 항목)과 ‘연결’ 행동을 함께 표시한다. 연결 시작 뒤 출발 블록·경로·대상 선택 안내를 지속 표시한다.
- 연결 가능한 블록은 테두리뿐 아니라 ‘여기로 연결’ 문구로 안내한다. 포인터를 따라가는 미리보기 선은 저장된 연결과 구분한다. Esc/취소/빈 캔버스로 연결 모드를 끝낼 수 있다.
- 드래그 완료를 클릭 선택으로 처리하지 않는다. 이동 중에는 설정 패널을 열거나 실행 순서를 바꾸지 않는다. 키보드 위치·대상 선택도 유지한다.
- 최종 결과는 기본 블록 한 개로 제공하고 추가 목록에 넣지 않는다. 기존 다중 결과는 자동 삭제하지 않고 사용자가 여분을 정리하도록 한다.
- 작업 추가는 직접 AI 구성/ASA 기본 도구/내 에이전트로 구분한다. 직접 구성은 지시문·모델·입력·출력, 기존 작업은 설명·버전·입력 계약을 표시한다.
- 모델 선택지는 서버 허용 목록에서 받는다. 빈 목록과 로딩 실패를 구분하고 임의의 사용 가능 모델을 표시하지 않는다. 모델명/공급자는 표시해도 비밀키는 표시하지 않는다.

### 복잡한 연결 추적 (ASA-039)
- 교차선은 배경색 외곽선으로 분리해 교차점이 합류점처럼 보이지 않게 한다.
- 연결선 클릭/Enter/Space 또는 검색 가능한 연결 목록으로 추적한다. 선택선은 맨 위에 강조하고 출발·경로·도착 이름을 텍스트로 표시한다. 양끝 블록을 강조하며 다른 선은 흐리게 표시한다.
- 완전히 겹친 선도 목록으로 선택할 수 있어야 한다. 선택한 연결만 보기와 전체 연결 복귀/Escape를 제공한다. 색상만으로 관계를 전달하지 않는다.
- 선택/검색은 보기 상태이며 저장된 그래프나 실행 순서를 변경하지 않는다. 선의 기하학적 겹침을 모두 제거했다고 표현하지 않는다.

### 전체 연결 자동 분리 (ASA-040)
- 개별 연결이 아닌 전체 연결을 기하 위치/포트/ID의 안정된 순서로 계산한다. 앞선 경로와 나란한 구간은 12px 간격을 확보하며 다른 통로를 찾는다.
- 한 블록으로 모이는 연결은 왼쪽 진입 높이를 나눈다. 포트·실행 순서·블록 좌표는 변경하지 않는다.
- 모서리는 둥글게 하고 경로 탐색에서 불필요한 꺾임에 비용을 부여한다. 수직 교차는 기존 외곽선으로 구분한다. 공유 구간 회피와 교차 없는 평면 배치는 구별한다.
- 공간 부족 시 연결을 숨기거나 끊지 않는다. 안전한 기존 경로로 표시하고 간격 부족을 안내한다. 드래그 중 임시 선, 놓은 뒤 전체 재계산 정책은 유지한다.

### 메뉴와 블록 편집 접근 (ASA-041)
- 데스크톱 GNB는 상단 메뉴 접기/열기 버튼으로 제어한다. 상태를 브라우저에 저장하되 저장소가 막혀도 현재 화면에서 작동한다. 고객/관리 화면에 동일 버튼을 쓴다. 모바일의 기존 메뉴는 유지한다.
- 블록 카드에 설정 버튼을 항상 표시한다. 설정 패널 상단에서 블록 이름, 입력/출력 연결 개수와 삭제 버튼을 확인한다. 좁은 화면에서 설정을 캔버스 아래에 밀어두지 않고 우측 패널로 띄운다.
- 시작/단일 최종 결과는 삭제하지 않는다. 일반 블록 삭제는 연결선도 제거하며 다음 편집 전 삭제 취소를 제공한다. 참조 입력 확인 안내를 표시한다.

## 자동화 카드 (ASA-049)
공통 16px 모서리·24px 내부 여백·SVG 선 아이콘을 사용한다. 일반 제목20px, AI 제목24px, 설명15px, 메타12px로 위계를 구분한다. 시작/결과는 중복 유형 문구를 숨긴다. 설정은 접근성 이름과 툴팁이 있는 아이콘 버튼이다. AI 배경은 accent-soft, 안내는 warning 토큰을 사용한다. 단일 연결점은 중앙이고 클릭 영역44px/시각 지름16px를 유지한다. 치수는 graph-card-layout.ts를 단일 기준으로 삼는다.

## 시안 기준 타이포그래피 (ASA-050)
공통 UI는 로컬 제공 Pretendard Variable v1.3.9를 사용한다. fonts/Pretendard-LICENSE.txt의 SIL OFL을 동봉한다. 출처 https://github.com/orioncactus/pretendard . body와 입력/select/button/textarea가 동일한 글꼴을 상속한다. 빌더 토큰: flow-title28px, label14px, body16px, meta13px, 일반 제목22px/750, 아이콘28px/배경52px. 이전 ASA-049의 글자 크기 정의를 대체한다. 설정은 3줄 조절 아이콘, 검색은 지구본 아이콘이다. 이미지 시안은 방향을 정하는 참고이며 이 문서와 tokens.css가 구현 규격이다.

## 탐색 및 블록 겹침 (ASA-051)
데스크톱 GNB 접기/열기 아이콘은 GNB 내부에 둔다. 접힘은 64px 레일을 유지하며 모바일 메뉴는 기존 방식이다. 공급자 로고는 텍스트와 함께 사용한다. OpenAI(Simple Icons13), Claude(Simple Icons15) SVG를 로컬 제공하고 CC0 라이선스를 동봉한다. 도구는 플러그, 에이전트는 로봇 아이콘이다. 새 블록/드롭은 다른 블록과24px 간격을 두는 가까운 빈 위치로 옮기며 이웃 블록은 유지한다. 기존 겹침은 전체 블록 목록에서 선택하거나 간격 정리로 해소한다. 선택/이동 블록을 앞으로 표시한다.

## 자동화 목록 카드 (ASA-052)
목록 카드는 20px 모서리·24px 여백·44px 아이콘을 사용한다. 상단 아이콘과 버전, 제목18px/최대2줄, 설명14px/최대3줄, 블록 수와 편집, 하단 실행/예약/기록 순서다. 같은 행의 카드 높이와 버튼 위치를 맞춘다. 실행만 primary, 예약/기록은 secondary이며 42px 이상의 버튼 높이를 유지한다. 제목과 편집으로 편집 화면에 접근한다. 설명 전체는 title 속성으로 제공하며 좁은 화면은 단일 열로 전환한다. 색상은 공통 테마 토큰을 따른다.

## 관리자 AI 모니터링 (ASA-054)
필터 → 요약 지표 → 모델/작업 집계 → 호출 기록 → 요청 상세 순서로 보여준다. 관리자 GNB에서 접근하며 실제 역할 검사는 API가 수행한다. 표는 좁은 화면에서 내부 스크롤하고 페이지 전체를 가로로 넘치게 하지 않는다. 날짜/검색/선택에는 label을 제공한다. 요청 상세는 선택 후 포커스를 이동하고 전문은 disclosure로 펼친다. null 금액·토큰·시간은 ‘미확인’으로 표시하며 숫자 0과 구분한다. 예상 비용에는 USD와 누락/부분 집계 안내를 함께 표시한다. 다크 모드 색은 기존 테마 토큰을 사용한다.

ASA-055: 모니터링 기본 필터는 기간·검색·조회 버튼과 상세 조건 토글만 표시한다. AI 서비스/출처/상태는 기본 접힘이며 값은 유지한다. 적용된 상세 조건은 태그와 개수로, 조회 전 변경은 별도 안내로 구분한다. 상세 초기화는 입력만 초기화하며 조회로 적용한다. 모바일은 날짜 2열과 검색 전체 너비를 사용한다.


## 설정 화면 배치 (ASA-060)
- 공통 `SettingsSection`은 카드 제목·설명·우측 동작과 본문을 나눈다. 제목 행은 세로 중앙 정렬,
  동작은 오른쪽에 배치하며 좁은 화면에서만 줄바꿈한다. 제목/설명의 기본 margin을 제거한다.
- 섹션 간격/카드 패딩 24px, 필드 간격 16px, label→입력→도움말 간격 8px를 토큰으로 공유한다.
  설정 카드 높이는 auto이며 내용에 맞춘다. 입력과 select는 44px 높이를 공유한다.
- 병렬 필드는 위쪽 기준 정렬한다. 도움말이 있는 필드 때문에 다른 필드의 입력 위치를
  아래로 밀지 않는다. 도움말은 입력 아래에 두며 체크박스 행은 44px 클릭 높이·8px 간격이다.
- 펼침 영역은 상단 경계선/16px 여백으로 구분한다. 저장 영역은 24px 상단 간격과 경계선,
  왼쪽 안내·오른쪽 취소/저장 동작, 버튼 사이 12px를 사용한다. 모바일에서는 버튼을 같은 너비로 둔다.
- 모델 관리 화면은 키 설정 상태 → 기본 모델 → 사용 가능한 모델 → 저장 순서다.
  키 존재와 API 인증 성공을 구분하고, 기본 모델은 명시 선택을 덮어쓰지 않는다는 안내를 둔다.
- 화면 검증 시 데스크톱 입력 상단/높이와 체크박스 행, 펼침 전후/빈 목록/모바일 넘침을 확인한다.


## 모델 선택 콤보박스 (ASA-062)
검색과 선택은 단일 입력으로 제공한다. role=combobox/listbox/option과 aria-expanded/activedescendant를 사용한다. 방향키 이동·Enter 선택·Escape 닫기·Tab 이탈을 지원한다. 목록은 280px 이내 스크롤, 입력은 공통44px 높이, 표면/강조/텍스트는 디자인 토큰을 사용한다. 공급자 자동 조회 중 비활성 및 안내, 실패 시 오류·재시도, 검색 결과 없음 상태를 제공한다.

## 공통 선택창 (ASA-063)
`components/ui.tsx`의 SelectCombobox를 사용한다. 공급자처럼 선택만 필요한 경우 searchable=false, 모델처럼 검색이 필요한 경우 true를 지정한다. 두 모드 모두 44px 높이·10px 반경·동일 패딩/글꼴/SVG 화살표/목록 강조/키보드 포커스 스타일을 공유한다. 기능 차이를 위해 브라우저 기본 select와 별도 검색형 디자인을 혼용하지 않는다.

## 다수 모델 관리 (ASA-064)
반복되는 대형 편집 폼을 목록에 쌓지 않는다. 요약 행(이름·상태·설정 동작)과 단일 상세 패널을 사용하고 목록 자체는 최대360px 내부 스크롤로 제한한다. 상세 상태를 aria-expanded로 알리고 키보드로 행을 선택할 수 있어야 한다. 비용 수동 입력과 캐시 고급 항목은 단계적으로 펼친다.

ASA-065: 모델 공식 정보는 내용 너비의 배지와 우측 갱신 동작을 flex 행에 정렬한다. 안내·확인 시각·출처는 12px 간격과 보조 글꼴을 사용한다. 요율은 읽기 전용 표로 제공하며 직접 입력은 별도 계약 고급 영역에만 둔다.

ASA-066: 모델 관리의 작업명은 패널 열기(+ 새 모델), 영구 등록(선택한 모델 등록), 기존 편집 저장(편집 내용 저장)을 구분한다. 동일한 모델 추가 버튼을 중복 사용하지 않으며 등록 성공은 DB 응답 후에만 표시한다.

ASA-067: 요율 편집 동작은 제목과 같은 행에 노출한다. 편집 진입을 위해 접힘과 버튼을 두 번 누르게 하지 않는다. 자동 표/직접 입력을 전환하며 동일 위치에 공식 복원을 표시한다.

### 에이전트 설정 용어 (ASA-069)
- 지침은 `에이전트 지침`, 입력 양식은 `사용자가 입력할 항목`으로 표기한다.
- `초안 저장`과 최초 `에이전트 등록`/이후 `새 버전 등록`을 구분한다. 저장 상태는 `초안 저장됨`으로 표시한다.
- 미리보기는 `실제 AI 호출 없음`으로 표시하며 API 연결 상태로 오해하게 표현하지 않는다.
- 도구·에이전트 연결 설정과 실제 호출 지원 여부를 제목 가까이 안내한다.

### 항목 도움말 (ASA-070)
공통 ui.tsx의 HelpText 및 Field.help를 사용한다. ? 버튼은 클릭/Enter/Space로 펼치고 다시 누르거나 Escape로 닫는다. aria-expanded/controls와 항목별 이름을 제공한다. 설명은 문서 흐름 안에서 표시해 모바일에서 잘리지 않게 하며, 터치 영역은 44px이다. 도움말은 사용자 선택 기준·예시·실제 지원 범위를 설명한다. 필수 제한과 오류는 도움말에만 숨기지 않는다.

### AI 전달 표시 (ASA-071)
Field.annotation과 설명 배지로 AI에 전달/실행 시 입력값 전달/자동화 응답 형식/관리용/호출 설정을 구분한다. 초안은 즉시 실행에 적용되지 않으며 저장·등록·미리보기 자체는 AI 전송이 아님을 안내한다. 개별 에이전트와 자동화 모두 등록된 사용자 출력 계약을 따른다.

ASA-072: AI 전달 표시는 HelpText.ai의 18px 선형 반짝임 SVG로 통일한다. 텍스트 배지와 ?를 중복하지 않고 하나의 아이콘을 클릭/키보드/터치하면 전달 범위와 도움말을 함께 표시한다. 접근 가능한 이름과 title에는 전달 의미를 유지한다.

ASA-073: 항목 표시는 14px 선형 SVG·24px 데스크톱 버튼·평상시 배경 없음으로 통일. AI=반짝임, 관리용=문서, 호출 설정=슬라이더. 터치 버튼44px는 유지하되 그림은14px로 고정한다. 관리용/호출 설정도 텍스트 배지 대신 아이콘 도움말을 사용한다.

ASA-074: AI 전달 표시 아이콘은 에이전트 설정 화면에만 사용한다. 고객 실행 화면과 실행 화면 미리보기의 입력란은 항목 이름·입력 컨트롤·필수/선택 안내만 제공한다.
## 개별 에이전트 실행 (ASA-076)
- 단독 실행은 선택한 에이전트의 요청과 답변 중심으로 표시한다. 실제 구성되지 않은 제작 단계·가상 후속 작업은 표시하지 않는다.
- 응답을 읽기 화면으로 한 번만 표시한다. JSON 원문은 고객 결과 화면에 노출하지 않는다. 현재 대본 응답은 제목/대본으로 표시한다.
- 직접 수정 시에만 입력 폼을 연다. AI 수정 요청/실행 이력은 접힌 상세로 제공하고, 버전·미저장 변경 보호를 유지한다.
- 자동화의 단계와 연결은 사용자가 구성한 흐름에서만 표시한다. 대본 결과를 확정해도 다음 단계가 자동으로 존재한다는 안내를 하지 않는다.
## 요청 원문과 테스트 구분 (ASA-077)
- 고객 입력은 '내가 보낸 요청' 아래 blockquote로 원문을 보존한다. 시스템 상태 설명을 원문에 덧붙이거나 접두사를 임의로 제거하지 않는다.
- 테스트 요청은 customer_requests.is_test 메타데이터로 목록/상세에 배지를 표시한다. 에이전트 이름이나 입력 키워드로 테스트 여부를 추정하지 않는다.
- 최초 실행에 시스템이 넣은 지시문은 '첫 답변 생성 요청'으로 설명하며, 사용자 수정 지시는 '내가 보낸 수정 요청' 인용문으로 표시한다.
- 에이전트 버전/답변 버전, 보낸 시각/상태 변경 시각을 구분한다.

ASA-078: 내가 보낸 요청 라벨은 원문과 같은 메시지 영역 안에서 바로 위 8px 간격에 둔다. 필드 설명은 메시지 밖에 두며 라벨과 원문 사이에 안내문을 넣지 않는다.

ASA-081: 범용 답변은 항목 설명을 제목으로, 문자열은 문단, 목록은 번호 목록, 불리언은 예/아니오로 표현한다. 직접 수정도 같은 스키마의 필드로 제공한다. 사용자에게 JSON 포장을 노출하지 않는다. 기존 제목/대본 결과는 과거 버전 호환 화면으로 유지한다.

## ASA-084 에이전트 입력 양식
입력 항목 카드는 이름·입력 방식, 선택지/범위, 필수 여부·기본값 순으로 배치한다. 짧은 글/긴 글/숫자/라디오/선택 목록/정수 슬라이더를 지원한다. 공통 Field·Button과 색상 토큰을 사용하며 라디오 그룹은 fieldset/legend, 슬라이더는 연결된 label/output과 키보드 방향키를 지원한다. 모바일은 한 열, 조작 영역44px. 기존 중첩 입력은 세부 형식에서 편집한다.
기본값은 새 실행에서만 채우며 다시 작업할 때는 과거 입력을 그대로 사용한다. 선택 항목은 비워 둘 수 있고 라디오/슬라이더는 선택 해제를 제공한다. 필수 슬라이더는 미선택 상태를 명시하고 제출을 차단한다. 설정 초안은 미리보기에 즉시 반영되며 실제 실행은 새 버전 등록 후 적용된다.

### 선택지 편집
- 라디오 버튼·선택 목록은 선택지별 단일 입력 행과 추가/삭제 버튼을 사용한다. 줄바꿈 같은 입력 규칙을 요구하지 않는다.
- 빈 값·공백·중복은 해당 행에서 안내하고 저장을 차단한다. 기본값인 선택지의 이름 변경은 기본값에 반영하고 삭제 시 해제 사실을 안내한다.
- 추가/삭제 후 해당 입력 행에 포커스를 이동한다. 최소 1개, 최대 100개를 유지한다.

### 에이전트 실행 전 배치
- 입력 준비 화면은 최대 960px 단일 열로 배치한다. 생성되지 않은 결과를 위해 별도 열이나 빈 결과 카드를 예약하지 않는다.
- 진행 상태와 실제 답변은 요청 접수 이후 해당 작업 화면에서 표시한다.

### 실행 입력 폼 간격 계약
- 폼 컨테이너가 입력 그룹 사이 간격(24px)을 담당한다. 개별 Field의 외부 margin을 중복 적용하지 않는다.
- 라디오 선택지 사이는8px, 선택지 목록과 선택 해제 버튼 사이는12px. 해제 버튼 유무에 관계없이 다음 입력 그룹과24px을 유지한다.
- 컨트롤과 하단 도움말은 Field의8px gap을 사용하며 p 기본 여백을 제거한다.
- 확인 범위: 첫 화면만 보지 않고 폼 전체의 그룹 경계, 선택/해제 상태, 하단 실행 버튼까지 실측한다.

### 에이전트 실시간 응답
공개용 요청 이해/작성 방향은 작은 제목과 본문으로 구분하고 내부 gap16px을 사용한다. 응답 영역 직계 카드는 height:auto로 콘텐츠 높이에 맞춘다. 생성 중 답변은 미완성 표시를 유지하며 실패 후 저장된 최종 답변처럼 표시하지 않는다. 상태는 움직임과 함께 텍스트로 제공한다.


## 캐릭터 검토 화면
- 섹션·필드 그룹 gap24px, label/control gap8px, 카드 padding24px. 공통 토큰 사용. 동적 내용 카드는 height:auto이며 기본 card height100%를 상속하지 않는다.
- 화면900px 이하에서 카드/입력2열을1열로 전환한다. 이미지 비율을 보존하고 빈 결과는 짧은 안내로만 표시한다.
- 생성 상태와 워커 상태는 텍스트로 표시한다. 버전 선택과 기준 확정은 분리하며 새 수정본으로 기존 기준을 자동 교체하지 않는다.

### 최근 작업 사이드바 높이
- 최근 작업은 --sidebar-recent-min-height(180px) 이상을 확보한다. 스튜디오 메뉴는 최대32dvh에서 독립 스크롤한다.
- 접기 버튼은 콘텐츠와 같은 세로 flex 컨테이너에 놓고, 콘텐츠는 남은 높이를 사용한다. 전체 공간이 부족하면 콘텐츠 전체가 스크롤되어 접근 불가능한 영역이 생기지 않도록 한다. 확대 배율은 사용자의 설정을 유지한다.

### 에이전트 설정과 카드
- 입력 항목 편집 본문은 전용 grid와 gap16px을 사용한다. `.stack` 간격에 `.actions` margin을 더해 중복 여백을 만들지 않는다. 본문 Field/p의 기본 margin은 제거하고 라벨·컨트롤 gap은 유지한다. 필수/기본값 체크박스는 가로 배치하며 좁으면 줄바꿈한다. 연결 이름과 삭제 버튼은 하단 행으로 묶고 삭제 버튼을 전체 너비로 늘리지 않는다.
- 체크박스 `.checkbox`는 부모 컨테이너와 무관하게 flex/align-items:center/gap8px을 적용한다. 체크박스는 20px, 기본 margin 0, 축소 금지이며 라벨 전체 클릭 영역은 최소44px이다. `.field-row` 등 특정 부모 아래에서만 공통 규칙을 정의하지 않는다. 선택/미선택 상태와 도움말 유무를 실제 화면에서 확인한다.
- 공통 Field의 라벨 행은 최소 44px로 맞춘다. 도움말의 터치 영역 유무가 나란한 입력창의 시작 높이를 바꾸지 않도록 한다. 입력 항목 그리드의 Field 상단 margin은 0이며 그룹 간격은 grid gap으로 관리한다.
- 에이전트 카드에는 AgentIcon을 사용한다. 고정 문자 A를 개별 에이전트 식별자로 쓰지 않는다. 카드 하단은 설명 길이와 관계없이 정렬한다.
- 답변 확인 설정은 답변 형식 아래에 항상 노출한다. 생성 완료와 사람의 확정을 구분하고, 확정이 필요한 답변에는 검토 상태와 확정 버튼을 함께 제공한다.

### 캐릭터 이미지 수정 영역
- 이미지·버전·확정 버튼은 항상 노출한다. 단일 캐릭터 작업 카드에서 모델/수정 요청/설정/제외는 기본 펼친 '수정 및 확인'에 묶고 필요하면 접는다. 진행·오류 상태와 새 버전 알림은 접힘 밖에 둔다.
- summary 최소44px, chevron과 텍스트 gap12px, 펼친 본문 상단/그룹 간격16px을 사용한다. 키보드 Enter/Space 및 focus-visible을 유지한다.

- 캐릭터 참고 정보는 '참고 정보 · 수정 가능' 영역에 묶고 대본 정보/AI 제안을 textarea로 제공한다. 우선 적용할 외형·의상/이미지 제작 지침과 시각적으로 분리하며, 영역 내부 padding/gap16px을 사용한다. 다음 이미지 요청 시 저장·적용됨과 기존 이미지 보존, 참고 변경이 다른 필드를 자동 수정하지 않음을 안내한다.
