# DB pooling and change-driven work (ASA-111)

Use psycopg_pool per process/DSN; repositories, auth and readiness borrow connections. LISTEN connections are dedicated, autocommit, shared per process/DSN. Transactions and advisory locks retain existing queue ownership semantics. Notification payload contains workspace UUID and topic only, never user content.

Transactional SQL triggers notify state changes after commit; queue channels only on enqueue/resume, not heartbeat/stream writes. API SSE subscribes before initial snapshot to avoid races; memory revision wakes reload; unchanged snapshots are suppressed. Keepalive carries no DB query. Reconnect reloads authoritative DB state. 45s stream lifetime retains authentication refresh and fallback recovery. Worker idle waits up to30s for notifications, then performs bounded recovery/heartbeat; schedules wake at next due time. Healthy idle is not zero DB activity: heartbeat/recovery retained deliberately.
