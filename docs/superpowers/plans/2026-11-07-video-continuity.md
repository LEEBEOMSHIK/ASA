# Video continuity implementation plan

**Goal:** 연속 동작 클립은 앞 클립의 확정 영상 마지막 프레임으로만 생성한다.
**Architecture:** 기존 계획에 connection_type(cut/continue), previous_clip_id를 추가한다. API에서 승인된 부모 작업 ID와 SHA256을 고정하고 워커가 다시 검증한다. 기존 계획은 cut으로 해석한다.
**Spec:** 사용자 승인: 공통/스타일 지침, 화면과 생성 경로에 연결 정보 적용, 앞 영상 확정 전 다음 연속 영상 차단.
**Constraints:** workspace 격리, 기존 작업/설정 보존, 유료 호출 없음, 이미지 생성 관리 UI 변경 없음.

- [x] 계약/지침: 잘못된 부모, 첫 클립 연속, 컷의 부모 참조 거부 테스트 후 구현. 기본 템플릿과 실행 제약에 연결 규칙 반영.
- [x] API/워커: 확정 이전 접수 차단, 동일 요청/버전 부모 고정, 해시 재검증, 마지막 PNG 추출 및 시작 이미지 제공. 모의 공급자 테스트로 호출 차단 검증.
- [x] UI: 의존성/시작 이미지/대기 표시, 생성 선택 제한, 기존 간격 유지. API 오류 메시지 추가.
- [x] 검증: pytest/ruff/mypy/typecheck/build, 브라우저 가능한 상태 검증, 미검증 기록.

검토 초점: 다른 workspace 참조, 일괄 부모+자식 접수, 확정 이후 영상 변경, 기존 계획 호환성, 추출 실패 시 외부 호출 없음.
자동 조립·오디오 믹싱·자막·공급자 연장 API는 이번 범위에 포함하지 않는다.

실행 기록: 컷의 previous_clip_id는 기존 출력 계약의 문자열 타입에 맞춰 빈 문자열로 정의. 리뷰에서 패딩 후 연속 연결의 종료 프레임 불일치를 발견해 해당 조합을 거부하고 회귀 테스트 추가. 원래 지침을 보존한 추가 저장 revision10, 이전 요청 스냅샷 유지. 조회는 PostgreSQL SHA256과 요청 내 참조 사슬로 검증하여 폴링마다 전체 영상 bytea를 가져오지 않음.
