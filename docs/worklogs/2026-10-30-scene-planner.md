# 장면 구성 에이전트 및 대본 연결 검증

사용자 승인 범위: 장면 구성 에이전트를 등록하고 기존 무서운 쇼츠 대본으로 단독 테스트한 뒤, 성공하면 두 에이전트를 자동화로 연결해 실제 단계별 결과를 확인한다.

## 등록 및 연결

- 장면 구성 에이전트 v1: `f0fb2021-93a2-4004-80dc-e7874224dce9`. 재사용 가능한 정의는 `docs/agent-templates/scene-planner.json`.
- 필수 입력 `script`(대본), 선택 입력 `visual_style`(화면 스타일), `character_notes`(공통 인물 설정). 출력은 읽기 쉬운 한국어 자유 텍스트.
- 원문의 사건·인물·결말을 유지하며 장면별 대응 대본 구간, 예상 시간, 화면, 등장인물, 카메라·효과음을 작성한다. 원문에 없는 외형은 연출 제안으로 구분한다. 이미지 생성은 수행하지 않는다.
- 자동화: `어린이 공포 동화 · 대본에서 장면 구성까지`, ID `1c8fa557-bdb8-4700-bddd-54248b788b58`, 구성 v1.
- 시작 입력 → 무서운 쇼츠 대본 작가 v1 → 장면 구성 에이전트 v1 → 결과. `writer` 전체 출력 → `scenes.bindings.script`로 직접 연결한다.
- 현재 자동화 시작 UI는 단일 텍스트를 받는다. 이 자동화에서는 주인공 설정으로 사용하며, 나이 6~7세·무서움 2단계·길이 5분 등은 블록의 고정 입력이다. 사용자별로 바꾸려면 빌더에서 수정한다. 모든 항목을 실행 폼에서 바꿀 수 있다고 주장하지 않는다.
- 기존 대본 작가의 지침·등록 버전·기존 요청은 수정하지 않았다. 등록/실행은 인증·CSRF가 적용된 로컬 API를 사용했다.

## 실제 실행 결과

1. 단독 첫 시도 `970bc09b-1ea3-49ae-986f-22f857b5b42d`: 약25초 후 unknown. 부분 답변은 7번째 장면에서 끝났으며 사용량·비용은 미확인. 기존 2,048 출력 토큰 상한으로 장문 구성이 부족할 가능성이 있으나 저장된 오류만으로 원인은 확정하지 않는다. 기록 보존, 자동 재시도 없음.
2. 로컬 `.env`의 `ASA_SCRIPT_OUTPUT_TOKENS`, `ASA_AUTOMATION_OUTPUT_TOKENS`를 8,192로 설정했다. 진행 중 요청0건 확인 후 기존 script worker 프로세스들을 종료하고 하나를 재시작했다. 코드의 기본값은 바꾸지 않았다. 출력 상한 증가는 긴 답변의 최대 비용을 높일 수 있다.
3. 별도 단독 테스트 `ee9d0219-6120-405f-9688-12414ea201f6` 성공: 기존 완성 대본 전체를 입력. 12장면, 시간 합계300초, 출력3,874자. 인물·사건·반전·결말 보존 및 제안 외형 구분을 검토했다. 실제 음성 길이는 측정하지 않았다.
4. 자동화 실행 `42cab624-714c-4733-bf71-5015208aa34c` 성공: 대본2,581자 → 장면 구성4,206자/14장면. 저장된 `writer.output == scenes.input.script` 문자열 완전 일치 검증. 장면 시간 합계300초. 시작·두 에이전트·결과 블록 모두 succeeded.
5. 꺼져 있던 자동화 워커를 실행했다. 시작 전 다른 대기 요청0건, 활성 예약0건 확인. 실제 브라우저의 자동화 실행 기록에서 전체 완료와 두 단계 출력 표시 확인.

## 확인 범위와 남은 사항

- UI 확인: 자동화 목록에 등록, 실행 기록 열기, 전체 완료와 각 단계의 실제 결과 표시. 긴 결과는 현재 기존 렌더러의 원문 마크다운 형태로 표시되며 결과 중복 표시도 남아 있다. 이번 작업에서 UI를 새로 설계하지 않았다.
- 웹 프록시를 통한 단독 상태 조회가 두 차례 일시적으로500을 반환했다. API 직접 조회로 동일 요청의 최종 상태를 확인했으며 새 호출로 대체하지 않았다. 후속 브라우저 자동화 기록 조회는 정상. 프록시 오류 원인을 해결했다고 주장하지 않는다.
- 원본 대본/생성 답변/사용량 원문은 Git 제외 `.local/verification/scene-*.json`에만 저장했다.
- 회귀 검증 결과는 WORKBOARD.md ASA-098에 기록한다.
