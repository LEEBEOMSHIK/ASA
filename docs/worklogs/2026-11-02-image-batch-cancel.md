# ASA-160 캐릭터 이미지 일괄 생성과 대기 취소

- 캐릭터 결과 상단에 선택형 일괄 생성 패널 추가. 미생성/실패/취소 후 이미지 없는 캐릭터만 선택 가능하며 사용 안 함·기존 이미지·진행 중·결과 불명은 제외한다.
- 전체 선택/해제, 공통 모델, 선택 수와 유료 API 안내. 각 카드에서 수정 중인 설정을 전달하며 기존 이미지나 확정 기록은 변경하지 않는다.
- 최대 12개 요청을 하나의 DB 트랜잭션으로 접수한다. 중간 검증 실패 시 모두 롤백한다. 요청 ID 재사용으로 응답 유실 재전송의 중복 접수를 방지한다.
- 대기 중 요청만 취소한다. 워커가 먼저 claim한 경우 409로 안내하고 최신 상태를 갱신한다. 취소는 기록을 보존하고 이미지 API를 호출하지 않는다. 실행 중 외부 호출은 취소를 보장하지 않으며 비용 발생 가능성을 안내한다.
- 취소된 새 버전은 작업 완료 상태 산정에서 제외하여 기존 확정 상태를 복원한다. 기존 이미지가 없다면 미생성 상태로 돌아간다. SSE의 기존 DB 변경 알림을 사용한다.

## 검증

- 전체 backend pytest: 255 passed (88.39s).
- backend src ruff, mypy 48 files, frontend typecheck/build, git diff --check 통과.
- 전체 tests ruff: 기존 71건 유지. 이번 추가 테스트의 lint 오류는 없음.
- DB 통합 테스트: 원자적 롤백, 동일 요청 재전송, 중복 항목 거부, workspace 격리, 반복 취소, 실행 시작과 취소 경쟁, API 미호출, 확정 이미지 보존, 인증/CSRF.
- 실제 localhost 화면의 다크 모드에서 패널 열기 및 빈 대상 안내를 스크린샷으로 확인했다. 확인 당시 기존 7명 이미지는 모두 생성 완료되어 실제 사용자 데이터로 선택 생성/취소 버튼을 제출하지 않았다. 해당 동작은 격리 DB 테스트로 검증했으며 추가 유료 호출은 하지 않았다.
- ASA API만 재시작하여 신규 batch/cancel 경로 반영 확인. 기존 워커는 유지했다.

## 한계

- 일괄 접수 후 실제 생성은 기존 워커에서 순차 처리한다.
- 외부 이미지 API 호출이 시작된 작업을 강제 중단하거나 이미 발생한 비용을 취소하는 기능은 제공하지 않는다.
- 이번 작업에서 모바일 화면과 실제 유료 이미지 생성은 검증하지 않았다.
