# ASA-111 DB 연결 풀과 변경 알림

## 적용 내용
- 일반 DB 접근을 프로세스별 연결 풀로 전환했다(최대 8개). 트랜잭션 종료 후 연결을 재사용한다.
- PostgreSQL LISTEN/NOTIFY로 큐 접수와 상태 변경을 알린다. 업무 데이터 commit 이후 알림을 보내며 workspace UUID와 토픽만 포함한다.
- SSE는 최초 상태와 실제로 바뀐 상태만 전송한다. keepalive는 DB를 조회하지 않는다. 캐릭터와 자동화 화면의 주기 조회도 SSE로 바꿨다.
- 유휴 워커는 알림을 기다린다. 복구와 heartbeat 확인은 최대 30초 주기이며, 예약 작업은 다음 예정 시각을 고려한다.
- 풀 안에서 중첩 연결을 빌려 교착되는 경로를 제거했다. advisory lock 해제 실패 시 연결을 폐기한다. 다른 워커가 잠금을 보유한 경우 대기하며 재조회 반복을 막는다.

## 로컬 적용과 확인
- 실행 중인 큐 작업이 없는 것을 확인한 뒤 migration과 API/에이전트/이미지/자동화 워커 재시작을 수행했다.
- 유휴 상태 10초 측정: 적용 전 신규 연결 56개/트랜잭션 133회, 적용 후 신규 연결 0개/트랜잭션 15회. 후자는 최근 작업 및 캐릭터 SSE 화면을 연 상태였다. 단일 관측 구간의 결과이며 항상 0회 조회를 의미하지 않는다.
- 실제 브라우저에서 최근 작업과 캐릭터 결과를 열어 검토 필요·미생성·확정 상태 및 기존 이미지 표시를 확인했다. 최근 작업/답변/캐릭터 SSE endpoint가 200으로 연결됐다.
- 테스트는 연결 재사용·rollback, commit 알림, workspace 분리, 알림 연결 복구, 대기 워커 깨우기, 중복 처리 방지, 동시 접수, 예약 시각, 잠금 대기, SSE 최초/변경 전송과 권한 검증을 포함한다.

## 범위와 제한
- 최종 검증: backend pytest 213 passed (87.84s), ruff(src)/mypy 통과. frontend typecheck/build 통과.
- 외부 유료 AI 생성은 새로 실행하지 않았다. 큐 회귀 검증은 가짜 생성기로 수행했다.
- SSE는 45초 재연결 시 권한과 최신 상태를 재검증한다. 최초 연결/재연결 snapshot과 keepalive는 유지된다.
- 알림은 영구 큐가 아니므로 DB 행과 저빈도 복구 조회가 기준이다. exactly-once를 보장한다고 주장하지 않는다.
- 사용자 데이터와 기존 결과를 변경하거나 확정하지 않았다. 커밋·push는 하지 않았다.
