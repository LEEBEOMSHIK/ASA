# ASA-075 고객 대본 실행 큐

## 구현
- PostgreSQL 내구성 큐와 상시 로컬 워커. 작업 공간별 1건씩 처리하며 중복 접수·경쟁 워커를 차단한다.
- 고객 실행 → 큐 접수 → AI 작성 → 제목/대본 표시 → 관리자 요청 추적을 연결했다.
- 공급자/모델과 등록된 에이전트 버전을 고정하며 호출 직전 허용 정책을 재검증한다.
- 기본 큐 100건, 일일 시작 20건, 출력 2,048토큰 한도. 불확실한 외부 호출은 자동 재시도하지 않는다.
- 접수 내용·적용 지침·대기 순서·경과 시간 표시, 상태 자동 갱신, 대기 취소를 제공한다. AI의 내부 추론을 표시하는 기능은 아니다.
- 상태와 결과를 동일한 DB 스냅샷으로 읽어 완료 시 결과가 누락되는 경쟁을 방지한다. 직접 수정한 결과도 고객 이력에 반영한다.

## 실제 로컬 검증
사용자 승인에 따라 쉬운 대본 작가의 도구 연결을 해제하고 보강된 지침으로 v3를 등록했다. 이전 등록 버전은 보존했다.

- 실제 유료 호출: 1회, 성공. 모델 gpt-6.1-terra.
- 요청 ID: b05622eb-8c37-49a8-b79d-403f1d9d4ae5
- 사용량 ID: 28bbfbd2-4809-479f-af1e-5b0dd294b29c
- 공급자 사용량: 입력 1,015 / 출력 288토큰. 소요 6,243ms. 예상 비용 USD 0.002455.
- 실행 화면 자동 결과 표시와 관리자 상세의 요청·버전·모델·응답·토큰·요율 연결 확인.
- 워커를 잠시 중단한 상태에서 대기 안내와 취소 확인 후 워커 재가동. 취소 요청은 AI를 호출하지 않았다.
- 비공개 로컬 스크린샷: .local/verification/script-queue-result.png, script-queue-monitoring.png, script-queue-waiting.png.

## 자동 검증 및 한계
다중 요청, 동일 요청 동시 접수, 경쟁 워커, 취소, 중단 복구, workspace 격리, CSRF, 모델 변경, 일일/큐 한도, 모니터링은 모의 AI와 실제 테스트 DB로 검증한다. 실제 공급자 다중 병렬 부하 시험은 수행하지 않았다.

현재 작업 공간당 순차 처리이며 도구 호출·다른 에이전트 위임은 제외한다. 워커/API/DB가 로컬에서 실행되어야 한다. 실행 중 프로세스가 끊긴 외부 호출의 exactly-once 또는 실제 과금 취소는 보장하지 않는다. 비용은 청구 확정액이 아닌 등록 요율에 따른 예상값이다.
