# ASA-162 · 씬 이미지 에이전트 원문·이미지 입력

## 반영
- 씬 이미지 에이전트 지침을 사용자와 합의한 원문/장면 대응, 확정 이미지 기준, 충돌·누락 표시, 연속성, 정지 이미지와 영상 메모 분리 규칙으로 교체했다.
- `script` 전체 대본 입력을 필수로 추가했다. 기존 scenes/characters/aspect_ratio 및 사용자 설정은 유지했다.
- 로컬 에이전트 `eed35913-04f5-444f-a6a1-f42f31d9567b` revision 2에 저장했다. 다른 6개 에이전트 정의·revision은 변경하지 않았다. 기존 요청은 원래 실행 설정을 유지한다.
- 개별 에이전트 큐와 수동 실행도 공통 확정 캐릭터 handoff 검증 후 실제 PNG를 LangChain HumanMessage에 첨부한다. 자동화는 기존 동일 경로를 유지한다.
- 원래 요청의 script/scenes/characters와 수정 요청의 이전 답변·수정 지시를 그대로 보낸다. 임의 URL 조회나 문자열 속 JSON 추측은 하지 않는다. characters에는 구조화된 handoff 객체가 필요하다.
- workspace·최신 확정 상태·제외 여부·이미지 존재·이미지 입력 모델 지원 검증을 재사용한다. 기준이 변경된 오래된 handoff는 그대로 사용하지 않는다.

## 검증
- 신규 이미지 전달 테스트 3개가 미구현 상태에서 실패한 뒤 구현 후 통과했다.
- 격리 PostgreSQL의 실제 확정 이미지 바이트 → 요청 저장 → 큐 → 모델 메시지 → 결과 저장 통합 검증 통과. 외부 모델만 대체했으며 재접수의 중복 실행 없음도 확인했다.
- 실제 로컬 테스트 자료로 대본 2,581자, 장면 4,206자, 확정 캐릭터 이미지 7장 모두 동일 모델 메시지에 포함됨을 확인했다. 원문 동일성, 이미지 지원 모델 검증 통과. 모델 호출 경계는 캡처로 대체하여 유료 호출 0건이다.
- pytest 전체 260 passed (91.02s), backend src/new-test ruff, mypy 48개 파일, frontend typecheck/build, git diff --check 통과.
- 큐 advisory lock을 획득하고 실행 중인 요청이 없음을 확인한 뒤 개별 에이전트 워커만 재시작했다. 새 프로세스 및 시작 오류 없음 확인. 이미지·자동화 워커는 유지했다.

## 범위와 사용
- 새 실행에서 대본 전체, 장면 구성 원문, 캐릭터 결과의 확정 캐릭터 전달 데이터를 입력한다. 자동화에서는 확정 캐릭터 가져오기 도구의 전체 결과를 characters에 연결한다.
- 실제 유료 AI 실행·계획 품질 평가는 이번에 수행하지 않았다. 결과 이미지 생성 도구/UI를 추가한 작업도 아니다. 이 에이전트는 장면 이미지 제작 계획을 작성한다.
- 사용자 이미지·원문은 문서나 Git에 복사하지 않았고 확인용 임시 스크립트는 ignored .local에 두었다. 커밋/푸시는 하지 않았다.
